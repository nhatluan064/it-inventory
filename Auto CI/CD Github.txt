Note Tổng Hợp: Thiết lập CI/CD với GitHub Actions & Firebase Hosting
## Phần 1: Thiết lập ban đầu (Làm một lần)
1. Tạo Service Account 🔑
Truy cập Google Cloud Console -> IAM & Admin -> Service Accounts.

Chọn đúng Project của bạn.

Nhấn "CREATE SERVICE ACCOUNT" và đặt tên (ví dụ: github-actions-deploy).

Gán Role: Firebase Hosting Admin.

Sau khi tạo, vào tab "KEYS" -> "ADD KEY" -> "Create new key" -> chọn JSON.

Một file .json sẽ được tải về. Lưu file này cẩn thận và tuyệt đối không commit lên Git.

2. Cấu hình GitHub Secrets 🤫
Vào Repository trên GitHub -> Settings -> Secrets and variables -> Actions.

Nhấn "New repository secret".

Tạo secret cho Service Account:

Name: FIREBASE_SERVICE_ACCOUNT

Value: Mở file .json đã tải, sao chép TOÀN BỘ nội dung và dán vào đây.

Tạo các secret cho biến môi trường (dựa trên file .env.example của bạn):

Lặp lại bước "New repository secret" cho mỗi biến. Ví dụ:

Name: REACT_APP_FIREBASE_API_KEY

Value: AIzaSyDS... (giá trị tương ứng)

## Phần 2: Cấu hình file Workflow
Tạo file tại đường dẫn .github/workflows/firebase-deploy.yml với nội dung hoàn chỉnh sau:

YAML

name: Deploy to Firebase Hosting

on:
  # Tự động chạy khi push lên nhánh main
  push:
    branches: [main]
  # Tự động chạy khi có Pull Request vào nhánh main
  pull_request:
    branches: [main]
  # Cho phép chạy thủ công từ tab Actions
  workflow_dispatch:

# Ngăn các lần deploy chồng chéo, tự hủy các lần chạy cũ khi có push mới
concurrency:
  group: hosting-deploy-main
  cancel-in-progress: true

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Use Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "npm"

      - name: Install dependencies
        run: npm ci

      # Tự động tạo file .env từ GitHub Secrets trước khi build
      - name: Create .env file
        run: |
          echo REACT_APP_FIREBASE_API_KEY=${{ secrets.REACT_APP_FIREBASE_API_KEY }} >> .env
          echo REACT_APP_FIREBASE_AUTH_DOMAIN=${{ secrets.REACT_APP_FIREBASE_AUTH_DOMAIN }} >> .env
          echo REACT_APP_FIREBASE_PROJECT_ID=${{ secrets.REACT_APP_FIREBASE_PROJECT_ID }} >> .env
          echo REACT_APP_FIREBASE_STORAGE_BUCKET=${{ secrets.REACT_APP_FIREBASE_STORAGE_BUCKET }} >> .env
          echo REACT_APP_FIREBASE_MESSAGING_SENDER_ID=${{ secrets.REACT_APP_FIREBASE_MESSAGING_SENDER_ID }} >> .env
          echo REACT_APP_FIREBASE_APP_ID=${{ secrets.REACT_APP_FIREBASE_APP_ID }} >> .env
          echo REACT_APP_FIREBASE_MEASUREMENT_ID=${{ secrets.REACT_APP_FIREBASE_MEASUREMENT_ID }} >> .env

      - name: Build
        run: npm run build

      - name: Deploy to Firebase Hosting (PR or main)
        uses: FirebaseExtended/action-hosting-deploy@v0
        with:
          repoToken: "${{ secrets.GITHUB_TOKEN }}"
          firebaseServiceAccount: "${{ secrets.FIREBASE_SERVICE_ACCOUNT }}"
          # Tự động deploy kênh live cho main, và kênh preview cho PR
          channelId: ${{ github.ref == 'refs/heads/main' && 'live' || 'pr-preview' }}
          projectId: it-inventory-108a0 # <-- Thay bằng Project ID của bạn
        env:
          FIREBASE_CLI_EXPERIMENTS: webframeworks
## Phần 3: Quy trình làm việc hàng ngày 👨‍💻
Quy trình chuẩn để kích hoạt tự động hóa: add -> commit -> push.

Sau khi code xong, chạy git add . để thêm các thay đổi.

Tạo commit với một lời nhắn rõ ràng: git commit -m "feat: Add new login feature".

Đẩy code lên nhánh main trên GitHub: git push origin main.

Workflow chỉ tự động chạy sau khi bạn push thành công lên đúng nhánh đã cấu hình (main).

## Phần 4: Gỡ lỗi & Xử lý sự cố 🐛
1. Lỗi Build do thiếu file .env
Nguyên nhân: File .env nằm trong .gitignore nên không tồn tại trong môi trường CI/CD.

Giải pháp: Thêm bước "Create .env file" vào workflow và tạo các secret tương ứng trên GitHub (như Phần 1 & 2).

2. Lỗi git push bị từ chối (Push Rejected / Secret Scanning)
Nguyên nhân: Vô tình commit phải file chứa thông tin nhạy cảm (như file .json).

Giải pháp: Phải xóa file đó khỏi lịch sử commit trên máy của bạn trước khi push.

Nếu chỉ bị ở commit cuối cùng:

Bash

git rm --cached <ten-file-bi-mat.json>
git commit --amend --no-edit
git push
Nếu bị ở nhiều commit cũ:

Bash

# Gộp N commit gần nhất lại
git reset --soft HEAD~N 
# Xóa file khỏi Git
git rm --cached <ten-file-bi-mat.json>
# Tạo commit mới đã được làm sạch
git commit -m "Consolidate commits and remove secret"
# Push với force-with-lease
git push --force-with-lease
3. Workflow không tự động chạy
Nguyên nhân: Bạn đang push lên một nhánh không phải là nhánh main.

Giải pháp:

Kiểm tra nhánh hiện tại: git branch

Chuyển về nhánh main: git checkout main

Gộp code từ nhánh kia vào (nếu cần): git merge <ten-nhanh-cua-ban>

Đẩy nhánh main lên: git push origin main

## Phần 5: Quản lý Key an toàn
GitHub Secrets là một chiều: Bạn KHÔNG THỂ xem lại nội dung của secret sau khi đã lưu.

Khi mất file .json: Đừng cố tìm lại. Hãy coi nó đã mất vĩnh viễn và thực hiện quy trình an toàn:

Vào Google Cloud Console để tạo một key mới (như Phần 1).

Vào GitHub Secrets để cập nhật secret FIREBASE_SERVICE_ACCOUNT với nội dung của key mới.

Vào Google Cloud Console để xóa key cũ đi cho an toàn.
